# i18n

Localization should be built into the project structure rather than patched on at the end.

Use English as the source/fallback language and keep gettext initialization isolated behind a small i18n boundary.

Validate the packaged/runtime locale behavior, not just the translation files. For Flatpak applications using the standard `.Locale` extension model, prefer a local repository install for localization QA so the application and its locale extension are tested together.

Verify the installed catalogs through the normal gettext path (`/app/share/locale`) and follow symlinks when necessary before changing working gettext initialization.

Use explicit `LANG` and `LANGUAGE` runtime smoke tests for the supported language matrix, and keep user/project data, identifiers, paths, filenames, MIME types, URLs, and application IDs untranslated.

See `learnings/gettext-runtime-locale-probe.md` for the evidence-backed local repository workflow and packaged-runtime boundary.
